# 05 · UI design

Clickable prototype: open [`prototype.html`](prototype.html) in a browser (no build step, made-up data). Sign in with a demo account: HR Admin (Priya Sharma) can change everything, HR Viewer (Arjun Mehta) can only view.

## 1. Goals
1. **Find anyone in under 5 seconds.** Search is always one keystroke away (`/`).
2. **Never lose your place.** The employee page keeps the list's filters and page, so Back returns exactly where you were.
3. **Numbers you can trust.** The currency is always shown; converted amounts are marked with "≈" and the date of the exchange rates used.
4. **Safe by default.** Bulk changes are previewed before saving; leaving the company is undoable.
5. **Simple.** Three areas, few colours, plain words.

## 2. Look and feel
Built with **shadcn/ui** (Tailwind + Radix), so the prototype already looks like the real components: white surfaces, thin borders, one accent colour.

| Token | Value | Use |
|-------|-------|-----|
| Background | `#FFFFFF` | Page and cards |
| Subtle | `#F7F7F9` | Table headers, hover |
| Border | `#E5E6EB` | All lines |
| Text | `#1B1C22` | Body text |
| Muted | `#6B6E7A` | Secondary text |
| Primary | `#2B50D6` | Main buttons, links, median marker |
| Band | `#C9D5FA` | Pay-range fill, histogram bars |
| Amber | `#B45309` | Unusual salaries (not red: high pay isn't an error) |
| Error | `#C4321E` | Validation problems only |

- **Font:** Geist, with tabular figures so salary columns line up. Sizes 13 / 14 / 15 / 24 / 30 px; weights 400 / 500 / 600.
- **One signature element: the pay band.** A thin range line (lowest to highest), a shaded bar (middle half of salaries), a blue tick (median) and, on an employee, a dot for that person. It is used on the employee page and in the Insights tables, and nowhere else.
- **Radius:** 8 px for controls, 10–12 px for tables and dialogs. A shadow only on the sheet and dialogs (they float).
- **Motion:** only when the user acts (a dialog or the mobile drawer opens, the progress bar moves). Off when the user prefers reduced motion.

## 4. Screens
### Home: calm, only what needs action
A greeting, three numbers (current employees, yearly salary cost, median salary), **Needs your attention** (people paid outside the usual range, salary changes starting in the next 7 days, imports waiting for review) and **Recent salary changes**. No charts here.

### People: filters in a left panel
- Left panel: Status, Country (top 5 + "Show more"), Department, Level (1–6 buttons), Employment type, Yearly salary range (USD). **Each option shows how many people it matches.** Filters apply instantly.
- Above the table: search, **active filters as removable chips**, the result count, Export CSV and "Show filters". The panel starts hidden so the table gets the full width; the chips still show which filters are on.
- Table: four columns (Employee, Role, Location, Yearly salary), each with a grey second line.
- On a phone: a "Filters (2)" button opens the panel as a bottom drawer; Role and Location columns are hidden.

### Employee page (/people/<id>)
Its own page (Q39), so each employee has a link and there's room for files. Back returns to the People list with the same filters and page.
- **Header:** photo or initials, name, role and level, status, actions (Change salary, Edit details, Mark as left). Viewers see no action buttons.
- **Salary:** yearly amount (local and USD with "rates as of <date>"), since when, any upcoming change; pay-range bar against the same role, level and country with a plain sentence ("Paid 12% more than the middle of this group").
- **Salary history:** date, amount, % change, reason, **changed by**.
- **Documents:** list with name, type, size, uploaded by and date; Upload (Admin, PDF/JPG/PNG ≤ 10 MB), Download, Remove (Admin).
- **Details:** employee code, email, department, location, employment type, part-time %, joined date, gender (optional; shown only here).

### Change salary (dialog)
New yearly amount with a live "+8.2%, ₹1,40,000 more a year" hint → start date (warns if more than 3 months in the past, explains future dates) → reason (required) → **Save salary change** → toast "Salary change saved".

### Insights: one question per tab
- **Overview:** pay by country or department (switch): people, median (local and USD), yearly cost, pay range bar.
- **By role:** one country at a time: each role and level with its range bar, median and an "unusual" badge; next to it, how salaries are spread (histogram).
- **Unusual salaries:** everyone paid outside the usual range for their role, level and country, with "+38%" style badges; "Open in People" shows them in the directory.

### Salary changes (/changes)
Every salary change across the company, newest first, 50 per page: employee (links to their page) and code, start date, yearly salary, reason, changed by ("Import" when it came from a file). Under the table: "51–100 of 35,330", Previous / Next and "Page 2 of 707" (the same pager as People). The page is in the URL (`?page=2`), so refresh and Back keep it; a page past the end offers a link back to page 1.

### Imports
Steps: **Upload → Check → Review → Apply → Done**.
Upload area with a template link → progress while checking ("Row 4,200 of 10,000. You can leave this page") → review with four counts (new, changes, no change, problems) and a table of problem rows → "Download problem rows" / "Save 1,246 correct rows" → finished summary. Previous imports are listed under the upload area.

## 5. Interaction details
| Situation | Behaviour |
|-----------|-----------|
| Typing in search | Waits 300 ms after typing stops; matches are highlighted |
| Filters | Active filters get a dark border; "Clear" appears when anything is filtered |
| Keyboard | `/` search, `↑ ↓` rows, `Enter` open, `Esc` close |
| Saving | Button shows a spinner and is disabled; success = toast; errors appear next to the field |
| Someone else changed the record | "This employee was changed by someone else. Reload to see the latest." |
| Too many requests | Toast: "You're going a bit fast. Try again in 20 seconds." |
| Long import | Progress shown on the Imports tab, so the user can keep working |

## 6. Accessibility
Not a goal for this assessment (Q32). We keep what shadcn/ui (Radix) gives for free: keyboard support, focus handling in dialogs, labelled controls. No formal testing.

## 7. Writing
Plain words and sentence case. Say "middle salary" alongside "median" the first time. The same name for an action all the way through: "Change salary" → "Save salary change" → "Salary change saved". Errors say what's wrong and how to fix it.

## 8. Building it
shadcn/ui components: `Table` (with TanStack Table), `Sheet`, `Dialog`, `Select`, `Input`, `Button`, `Badge`, `Toggle Group`, `Sonner` (toasts), `Progress`. Charts: Recharts (as used by shadcn charts). Custom: `PayBand` (small SVG component).
